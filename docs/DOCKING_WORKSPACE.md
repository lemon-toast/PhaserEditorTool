# 패널·도킹 워크스페이스

2026-10-21 추가 요구사항: 패널은 독립적으로 구성하고 도킹을 포함한 배치 기능을 제공해야 합니다. 아래 내용은 필수 설계이며 아직 구현하지 않았습니다.

## 패널 구성

| 패널 | 기본 배치 | 역할 |
| --- | --- | --- |
| Hierarchy | 왼쪽 | 노드 계층·선택·active |
| Scene | 중앙 | 배치 편집·실시간 미리보기 |
| Inspector | 오른쪽 | 선택한 노드 속성 |
| Assets | 아래쪽 탭 | 에셋 검색·추가 |
| Animation/Timeline | 아래쪽 탭 | 지정 연출·테스트 입력·재생·시간 표시 |
| Console | 아래쪽 탭 | 오류·경고·관련 항목 이동 |

배치는 기본값이며 고정하지 않습니다. Timeline 패널의 존재는 시각적 트랙 제작 UI 전체를 구현했다는 의미가 아닙니다. 우선 지정 연출 확인·시간 제어를 제공하고, 트랙 제작 기능 범위는 별도 설계를 따릅니다.

공통 툴바·상태 바는 창의 고정 영역입니다. 메뉴에서 패널 열기, 배치 선택·저장·초기화와 화면 밖 창 복구를 제공합니다.

## 필수 조작

- 헤더 또는 탭을 드래그하여 다른 영역의 상하좌우로 도킹하고 중첩 분할합니다.
- 영역 중앙으로 드롭하면 탭으로 묶습니다. 탭 순서를 바꾸고 다시 떼어낼 수 있습니다.
- 드래그 중 도킹 대상·미리보기 사각형을 표시합니다. 취소하거나 유효하지 않은 곳에 놓으면 이전 배치를 유지합니다.
- 분할 경계와 플로팅 창 테두리를 드래그해 크기를 조절합니다. 최소 크기 이하로 줄이지 않습니다.
- 메인 창 내부 플로팅과 별도 OS 창 분리를 지원하고 다시 도킹할 수 있습니다.
- 패널 단독 최대화·이전 배치 복원, 닫기·메뉴에서 재열기를 지원합니다.
- 최초 버전은 패널 종류별 논리적 인스턴스 하나를 사용합니다. 메뉴에서 이미 열린 패널을 선택하면 그 패널에 포커스합니다.
- 키보드 메뉴로 패널 열기·포커스·이동·배치 복구가 가능해야 합니다. Windows와 macOS의 단축키 표기를 구분합니다.

## 워크스페이스 저장

장면과 별도로 사용자별 워크스페이스를 저장합니다. 버전, panel ID, split 방향·비율, tab 목록·활성 탭, 플로팅 영역, 창 위치·크기와 복원용 소속을 기록합니다. 공통 기본 배치와 이름을 붙인 사용자 프리셋을 제공하고 마지막 상태를 자동 저장합니다.

장면 export에는 워크스페이스를 넣지 않습니다. 패널 이동·크기 변경은 장면 dirty나 Transform undo/redo에 영향을 주지 않습니다. 프로젝트별 마지막 배치가 필요하면 사용자 설정에서 프로젝트 식별자로 구분합니다. 다른 OS·모니터에서 가져온 배치는 현재 표시 영역에 맞게 보정합니다.

손상된 설정은 원본을 보존하고 기본 배치로 복구합니다. 알 수 없는 panel ID는 무시하고 필수 패널은 메뉴에서 다시 열 수 있게 합니다. 모든 패널을 닫아도 공통 메뉴에서 복구할 수 있어야 합니다.

## 상태와 렌더러 수명주기

도킹 트리는 UI 위치만 소유합니다. 장면 문서, 선택 ID, 수정 여부, undo/redo와 연출 재생 상태는 별도 store/runtime이 소유합니다. 패널 닫기나 이동으로 이 상태를 삭제하지 않습니다.

Scene 영역 크기가 변하면 viewport를 갱신하고 편집 좌표계·선택 hit test를 다시 계산합니다. 기본 Transform이나 게임용 해상도는 패널 크기에 따라 변경하지 않습니다. 캔버스가 숨겨지거나 크기가 0일 때도 잘못된 비율·NaN을 문서에 쓰지 않습니다.

같은 창 안에서는 가능한 한 렌더러를 유지합니다. 별도 창으로 이동해 렌더러를 재생성해야 한다면 공통 clock을 잠시 정지하고 선택·재생 시각·seed·임시 상태 snapshot을 복원합니다. 코드 연출도 상태 복원 계약을 구현해야 하며, 이동할 때마다 처음부터 다시 시작하는 동작은 최종 완료 기준을 충족하지 않습니다.

## 별도 창과 다중 모니터

브라우저 기반 검증 단계에서는 내부 도킹·플로팅을 먼저 구현합니다. 전체 요구 완료에는 데스크톱 호스트를 통한 별도 OS 창·다중 모니터 기능이 필요합니다. Electron 등을 후보로 검증하며 패키지와 버전은 구현 시 확정합니다.

- 보조 창은 별도 프로젝트 문서를 복제하지 않고 같은 논리적 문서의 패널을 표시합니다.
- 편집 명령은 한 소유 store에서 순서대로 처리하고 다른 창에 상태 변경을 전달합니다. 중복 적용과 두 clock 실행을 방지합니다.
- 보조 창을 닫으면 패널을 메인 창의 복원 위치 또는 기본 위치로 되돌립니다. 문서나 선택 노드를 삭제하지 않습니다.
- 메인 창을 닫을 때는 전체 세션의 미저장 변경을 한 번 처리하고 보조 창도 정리합니다.
- 모니터 제거, 해상도·배율 변경, 이전 OS의 창 위치 복원 시 접근 가능한 표시 영역으로 옮깁니다. '모든 창 가져오기' 동작을 제공합니다.
- 창 간 재도킹, 단축키 포커스, 파일 접근과 서비스 수명주기를 Windows·macOS에서 각각 검증합니다.

도킹 라이브러리 선정 기준은 Vue 연결, 분할·탭·플로팅·다중 창 지원 범위, 저장 형식 버전 관리, 복구 기능, 렌더러 수명주기 제어, 접근성과 라이선스입니다. 다중 창을 지원한다고 표시한 것만으로 Phaser·Spine 이동까지 검증되었다고 가정하지 않습니다.

## 검수 기준

1. 여섯 패널 각각을 이동·분할·탭 묶기·분리·플로팅하고 크기를 변경합니다.
2. 닫기·재열기·최대화·복원·기본 배치 초기화가 동작합니다.
3. 이름 있는 배치와 마지막 배치를 저장하고 재시작해 복원합니다.
4. 도킹 중에도 선택·미저장 편집·undo/redo가 유지되고 잘못된 드롭은 기존 배치를 보존합니다.
5. 승자승 연출 중 일시정지한 뒤 Scene·Timeline을 옮겨도 같은 재생 시점과 화면 상태를 복원합니다.
6. 별도 창에서 수정한 Transform이 다른 패널에 즉시 반영되고 export 데이터에도 한 번만 적용됩니다.
7. 보조 창 닫기·모니터 제거·손상된 배치·화면 밖 위치에서 복구하며 장면 데이터는 보존합니다.
8. Windows·macOS에서 파일·단축키·배율·다중 모니터 동작을 확인하고 렌더러·timer가 누적되지 않습니다.
