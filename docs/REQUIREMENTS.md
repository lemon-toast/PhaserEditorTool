# 요구사항

## 배경과 목표

현재 Phaser 런처만으로는 이미지·Spine·이펙트가 어느 위치에 어떻게 겹쳐 보이는지 확인하기 어렵습니다. layout 파일을 수정한 뒤 실행 결과를 반복해서 확인해야 합니다.

에디터는 개발자가 **현재 화면의 구성 요소를 계층으로 보고, 켜고 끄고, 배치를 바꾸면서 결과를 바로 확인**할 수 있게 합니다. Unity 전체 기능을 재현하는 것이 목적은 아닙니다.

사용자가 명시한 우선순위는 다음과 같습니다.

1. 이미지·Spine·파티클 모두 시각적으로 확인
2. 계층 기반 구성
3. active on/off
4. 구현에 앞선 문서화

이하 세부 조작과 저장 방식은 이 요구를 구현하기 위한 초기 설계안입니다.

## 화면 구성

| 영역 | 역할 |
| --- | --- |
| 툴바 | 프로젝트·화면·방향 선택, 저장, 실행 취소·다시 실행, 재생 제어 |
| Hierarchy | 트리, 펼침·접힘, 선택, active 체크박스, 부모 변경, 형제 순서 변경 |
| Scene | 실제 에셋 미리보기, 선택 테두리·원점 표시, 드래그 이동, 확대·축소, 화면 맞춤 |
| Inspector | 선택 노드의 공통 속성과 타입별 속성 편집 |
| Assets | 에셋 검색, 이미지·Spine 목록, 화면에 추가 |
| 상태 표시 | 로딩·저장 상태, 누락 에셋과 변환 미지원 항목 안내 |

## 기본 작업 흐름

1. 게임 프로젝트를 연결하고 화면 또는 layout을 선택합니다.
2. 이미지·Spine·파티클이 Scene에 표시되고 Hierarchy에 노드가 나타납니다.
3. 노드나 부모 그룹의 active 체크박스를 변경하여 표시 결과를 확인합니다.
4. 화면 또는 트리에서 노드를 선택하고 위치·배율 등을 수정합니다.
5. 애니메이션과 파티클을 재생하거나 정지하여 겹침과 배치를 확인합니다.
6. 에디터 문서를 저장하고 다시 열어 같은 상태를 복원합니다.

## 계층 및 active 규칙

- 노드 타입: `group`, `image`, `spine`, `particle`, `text`.
- 부모·자식 관계, 형제 순서, 고유 ID, 이름을 가집니다.
- `activeSelf`는 노드 자신의 체크박스 값이며 저장 대상입니다.
- `activeInHierarchy`는 자신의 activeSelf와 모든 조상 activeSelf를 AND한 계산값입니다.
- 부모를 꺼도 자식의 activeSelf는 바뀌지 않습니다. 부모를 다시 켜면 자식의 이전 선택이 복원됩니다.
- 부모 때문에 꺼진 자식은 트리에서 흐리게 표시하고 원인을 확인할 수 있게 합니다.
- active가 꺼지면 화면 표시, 선택을 위한 hit test, 애니메이션 및 파티클 갱신을 중단합니다.
- 노드 자신·자손을 부모로 지정하는 순환 관계는 금지합니다.
- Scene에서는 비활성 노드를 선택할 수 없지만 Hierarchy에서는 선택·편집할 수 있습니다.
- 드래그 중 이동은 부모 기준 좌표로 변환합니다.
- 부모 변경 시 기본 동작은 화면상 위치·회전·배율 유지입니다. 정확히 표현할 수 없는 변환은 변경을 거부하고 이유를 표시합니다.
- 초기 렌더 순서는 깊이 우선 순회와 형제 순서로 결정합니다. 임의의 전역 depth 교차는 초기 범위에서 제외합니다.

## 공통 편집

- 이름, activeSelf, 로컬 X/Y, 배율 X/Y, 회전, 투명도 편집
- 이미지 크기와 origin 편집, Spine 원점 표시
- 부모 그룹 이동·배율·회전의 자식 반영
- 노드 추가·삭제·복제, 그룹 만들기, 계층 이동
- 선택 노드 드래그 이동과 Inspector 숫자 입력
- 주요 편집의 실행 취소·다시 실행. 한 번의 드래그는 한 작업으로 처리
- 에셋 검색, 선택 에셋을 화면 중앙에 추가
- 가로·세로별 문서 상태 분리, 기준 해상도와 viewport 비율 확인

## 이미지

- PNG/JPEG/WebP 등 실제 프로젝트가 사용하는 이미지 로드
- 크기, origin, 뒤집기, tint, 투명도 표시와 편집
- SlotClient에서 사용하는 9-slice 표시 검증
- 에셋 경로가 없거나 로드에 실패하면 노드를 유지하고 오류 자리표시자 표시
- 이미지와 Spine atlas 페이지를 구분하여 목록 표시

## Spine

- 최초 연동은 SlotClient의 JSON skeleton + atlas + atlas 페이지 이미지 조합
- 대상 에셋과 호환되는 Spine 런타임 사용, 로드 실패 이유 표시
- 애니메이션·skin 목록 조회와 선택, 반복 여부와 재생 속도 편집
- 기본 pose, 재생·일시정지·처음부터 재생
- 원점과 선택 범위 표시, 위치·배율·회전 편집
- 게임 플레이 이벤트·오디오 콜백은 미리보기에서 실행하지 않음
- 다른 버전의 Spine이나 binary skeleton은 호환성 조사 후 확장

## 파티클

- MVP는 Phaser emitter이며, Spine 내부 애니메이션 효과와 별도 노드로 구분
- 텍스처 선택, 방출 간격, 방출 개수, 수명, 속도 범위, 중력, 시작·끝 크기와 alpha 편집
- 연속 방출과 한 번 방출(burst) 미리보기
- 재생·일시정지·정지·재시작 제공
- 정지는 방출을 중단하고 기존 입자를 지웁니다. 일시정지는 현재 입자와 시간을 유지합니다.
- active를 끄면 기존 입자를 지우고 갱신을 중단합니다. 다시 켜면 처음부터 재생합니다.
- Spine은 active를 끌 때 진행 시각을 보존하고 다시 켜면 이어서 재생합니다. 재시작은 별도 버튼입니다.
- 전역 일시정지는 활성 노드의 시간을 동결합니다. active 체크값과 저장 데이터는 바꾸지 않습니다.
- emitter당 및 화면 전체의 최대 입자 수 제한을 두고 제한 도달을 표시합니다.
- JSON으로 표현 가능한 emitter 설정을 우선 지원하며 JS 함수 콜백, 게임 종속 zone·processor는 미지원으로 표시합니다.
- Cocos·Unity 등의 원본 파티클을 자동으로 동일 재현하는 기능은 MVP에 포함하지 않습니다.

## 화면 상태

- 일반, 프리스핀, 로딩, 메뉴 등은 독립 화면 또는 그룹 프리셋으로 선택합니다.
- 프리셋은 관련 노드의 activeSelf 조합을 적용하며 게임 로직을 실행하지 않습니다.
- 일반·프리스핀 배경이나 팝업을 모두 켜서 겹침을 점검하는 것도 허용합니다.
- 실제 릴 회전·패 분배 등 게임 진행은 MVP 대상이 아닙니다. 필요한 정지 상태는 샘플 데이터로 표시합니다.

## 저장·불러오기

- 에디터 전용 JSON에 schemaVersion, 출처, 해상도, 계층, 속성, activeSelf와 프리셋 저장
- 선택 상태·줌 등 에디터 UI 상태와 장면 데이터를 구분
- 에셋은 프로젝트 기준 상대 경로로 저장하고 에셋 원본은 복사하지 않음
- 저장하지 않은 변경 표시, 다른 문서로 전환하거나 새로 불러올 때 변경 손실 방지
- 잘못된 JSON, 중복 ID, 부모 누락, 순환 참조, 유효하지 않은 숫자는 열기 전에 검증
- 모르는 버전은 원본을 덮어쓰지 않고 오류 안내
- 저장 후 다시 열었을 때 배치·계층·active·애니메이션 선택·파티클 설정 복원
- 기존 TypeScript layout 수정과 게임 적용은 후속 어댑터 작업. JSON 저장만으로 게임에 반영된 것으로 표시하지 않음

## MVP 완료 기준

1. 이미지·Spine·파티클 노드를 같은 장면에 표시할 수 있습니다.
2. 3단계 이상의 부모·자식 계층에서 active 전파와 복원이 위 규칙대로 동작합니다.
3. 이미지·Spine·파티클을 화면에서 선택·이동하고 Inspector에서 수정할 수 있습니다.
4. 부모 변환과 형제 순서가 화면 결과에 반영됩니다.
5. Spine 애니메이션·skin 선택, 일시정지·재시작이 동작합니다.
6. 파티클의 연속 방출·burst, 일시정지·정지·재시작이 구분되어 동작합니다.
7. 저장·재열기로 문서 상태가 복원되고 주요 편집을 실행 취소할 수 있습니다.
8. SlotClient 한 화면을 실제 에셋으로 불러오며, 미지원 항목과 서버 없는 미리보기 한계를 화면에 표시합니다.
9. 누락 이미지·atlas 페이지·호환되지 않는 Spine 때문에 에디터 전체가 중단되지 않습니다.

## 후속 범위

홀덤·맞고 어댑터, 게임 실행 화면과 양방향 연결, TypeScript 원본 반영, 정렬·스냅·다중 선택, 타임라인, prefab, mask 및 blend mode의 상세 편집은 이후 검토합니다.
