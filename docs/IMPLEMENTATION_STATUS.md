# 구현 현황

기준일: 2026-10-23. 개발 버전 0.1이며 전체 요구사항 완료를 의미하지 않습니다.

다음 작업은 [개발 순서의 순차 작업 목록](ROADMAP.md#현재-순차-작업-목록)을 따릅니다. 게임 적용 안내·기본 다중 배치·에셋 교체·9-slice 상세 편집을 완료했으며, 다음은 **에셋·9-slice의 게임 적용 확대**입니다. 뒤이어 복합 연출 검수·게임 실행 연결, 프리팹, 다른 게임 어댑터, 데스크톱 배포·다중 창 검수를 진행합니다.

## 실행

Windows에서는 **에디터 실행.cmd**를 더블클릭합니다. 독립 창에서 **프로젝트 → 작업할 화면 → 선택한 화면 열기**로 진행합니다. **프로젝트 폴더 열기**에서 OS 폴더 선택 창을 사용하고, 편집 중에는 툴바 **프로젝트 / 화면 선택**으로 돌아갑니다. 시작 시 예제가 자동으로 열리지 않습니다.

최초 설치는 Node.js 22.12 이상에서 `npm ci`, `npx install-electron --no`를 실행합니다. `npm run desktop`도 같은 독립 창을 엽니다. 현재는 저장소와 node_modules가 필요한 개발 실행 방식이며 패키징된 배포용 설치 파일은 없습니다. macOS용 실행 스크립트는 포함하지만 macOS 실기 검증은 수행하지 않았습니다.

Electron이 내부 Vite 파일 API를 127.0.0.1:5175에 함께 시작합니다. 같은 실행 방식에서는 고정 origin으로 최근 프로젝트와 패널 배치를 보존합니다. 5175 포트를 다른 앱이 사용하면 실행 오류를 표시합니다. 에디터 중복 실행은 기존 창을 활성화합니다. 렌더러는 sandbox·contextIsolation을 켜고 Node 직접 접근을 끄며, preload는 폴더 선택·프로젝트 화면 전환·미저장 상태 알림만 제공합니다.

이웃 SlotClient·TemplateWebGame을 시작 화면에 표시하며 다른 폴더도 선택할 수 있습니다. 에셋은 복사하지 않습니다. SLOT_1002 화면 가져오기/적용은 지정된 이웃 SlotClient의 내장 어댑터에 한정합니다. 임의 TypeScript 모듈 실행은 제공하지 않습니다. TemplateWebGame은 공용 에셋을 빈 화면에 배치하는 범위이며 기존 홀덤·맞고 레이아웃 가져오기는 미구현입니다.

브라우저 개발은 `npm run dev`로 실행하며 폴더 절대 경로 입력을 사용합니다. `npm run preview`는 정적 빌드 확인용이며 프로젝트 파일 API를 제공하지 않습니다. 독립 창의 패널 플로팅도 현재 창 내부이며 패널별 별도 OS 창은 아직 없습니다.

## 구현하고 확인한 기능

- Inspector에서 같은 종류의 이미지·Spine 에셋 검색·교체, skeleton/atlas 동시 연결과 재생 설정 호환 검사. 배치·표시 크기 유지, undo/redo·장면 저장 복원 지원
- 이미지 9-slice 사용·해제, 위/오른쪽/아래/왼쪽 경계와 경계 배율 편집. 숫자 범위·표시 크기 검사, 로딩 후 원본 이미지 크기 초과는 오류 자리표시자와 콘솔로 안내
- 현재 참조가 목록에 없으면 연결 확인 안내. 파일 누락 시 노드를 유지하며 기존 오류 자리표시자 사용. 에셋·9-slice 변경의 게임 역적용은 여전히 미지원

- Ctrl/Shift(또는 Command) 클릭 다중 선택, 선택 묶음 드래그, 부모·자식 중복 이동 방지. 정렬·드래그는 한 번의 undo로 복구
- 화면 배치 도구에서 마지막 선택 원점 기준 X/Y 정렬, 간격을 지정하는 화면 좌표 격자 스냅. 선택·스냅 설정은 장면 및 게임 export에 저장하지 않음
- 다중 선택의 속성 입력·복제·삭제·부모/순서 변경은 마지막 선택 객체 대상. 외곽선 기준 정렬·균등 분배·범위 드래그 선택은 미구현

- Inspector에 선택 객체의 게임 적용 지원 속성·제한과 현재 배치 모드의 내보내기 검증 결과 표시. 실제 게임 저장·실행 성공과 구분하며 기존 내보내기 검증을 공유

- Vue·TypeScript·Phaser 기반 로컬 에디터
- Electron 독립 에디터 창, Windows 더블클릭 실행과 내부 프로젝트·화면 선택
- OS 폴더 선택, 최근 프로젝트, 기본 레이아웃·게임 적용본 선택 및 미저장 전환/닫기 보호
- 계층, 화면, 속성, 에셋, 연출/타임라인, 콘솔의 독립 도킹 패널
- Dockview 8.6.1(MIT)의 분할·탭·플로팅 기반, 패널 재열기·최대화·기본 배치
- 마지막 패널 배치 자동 저장, 이름 있는 배치 저장·불러오기. 브라우저 사용자 설정에 보관
- 부모·자식 계층, active 전파와 자식 체크값 보존, 펼침·접힘
- 노드 추가·삭제·복제·형제 순서 변경·부모 변경
- 부모 변경 시 월드 Transform 보존, 순환 관계·0 배율·표현 불가능한 shear 거부
- Inspector의 위치·배율·회전·투명도, 이미지 크기·origin·tint, 텍스트 편집
- 이미지·Spine·Phaser particle 동시 렌더링과 Scene 클릭·드래그·확대·화면 맞춤
- Scene의 현재 모드·맞춤 기준 보기 배율 표시, 화면 맞춤 완료 알림. 배치 편집은 상태 표시이며 화면 맞춤은 보기 배율만 초기화
- Scene의 해상도 입력 옆 배치 모드 드롭다운, 너비·높이·화면비·해상도 프리셋과 적용 버튼
- 단일 고정 화면 또는 반응형 배치 세트 선택. 모드별 해상도·계층·배치·연출을 한 `.scene.json`에 저장·복원하며 모드 추가·전환도 undo/redo 지원
- SlotClient 기본 레이아웃을 열면 사용 가능한 가로·세로 원본을 한 세트로 구성. 새 사용자 모드는 현재 배치를 복사하고 원본 게임 역적용 연결은 이어받지 않음
- Spine 4.3 JSON+atlas+다중 페이지 로딩, 애니메이션·skin·반복 선택, active 시 갱신 제어
- 파티클 방출 설정, active 비활성 시 입자 제거, 재생·일시정지
- Transform 트랙 기반 승자승 예제, 전체 재생·정지·반복·배속·도착값 편집
- 시간 커서로 Transform 평가. 편집 원본을 변경하지 않는 평가 함수
- JSON 저장·불러오기, ID·계층·트랙 검증, 주요 편집 undo/redo
- 누락 에셋 자리표시자, 늦게 완료된 로딩의 오래된 장면 반영 방지
- SlotClient 실제 가로·세로 layout → 배경·장식·캐릭터·릴 Spine·HUD·로딩 그룹 변환
- SlotClient 9-slice 값 반영. 실제 게임과 모든 항목의 픽셀 단위 일치 검증은 아직 수행하지 않음
- 게임용 패키지 형식, SlotClient 기본 배치 뒤에 적용하는 선택적 import 연결
- 장식 이미지·배경·캐릭터·릴 Spine의 배치·애니메이션 선택 정보 역적용
- 게임 전용 내보내기·직접 저장·백업·게임 적용본 재import와 원본 변경 검사

연결 설치와 지원 범위는 [슬롯 게임 역적용](GAME_INTEGRATION.md)을 따릅니다. **SlotClient는 슬롯, TemplateWebGame은 홀덤·맞고**입니다. TemplateWebGame은 읽기 전용 에셋 탐색 연결이며 게임 역적용은 아직 없습니다.

공통 툴바를 **작업**과 **데이터**로 분리했습니다. **작업 저장**(Ctrl/⌘ S)은 모든 배치 모드·기본 배치·트랙을 `.scene.json`으로 다운로드하며 **작업 불러오기**에서 다시 엽니다. 중간 재생 위치·패널 배치는 문서에 넣지 않습니다. 현재 저장은 파일 다운로드 방식이며 기존 파일 덮어쓰기·다른 이름으로 저장 대화상자는 미구현입니다.

**데이터 Import**는 게임 패키지 파일, **데이터 Export**는 현재 모드의 게임용 패키지를 대상으로 합니다. 작업 문서와 게임 패키지를 서로 다른 입력 경로에서 거부하며 기존 장면은 보존합니다. 데이터 Import·게임 적용본 불러오기는 작업 저장이 필요한 상태로 표시합니다. Export·슬롯에 적용은 작업의 저장 상태를 바꾸지 않습니다. 게임 패키지의 편집 문서가 없는 경우 현재는 Import를 지원하지 않습니다. 파일 전환·닫기 시 미저장 변경 보호를 유지합니다.

화면 패널에서 **배치 모드 → 너비·높이 / 화면비·해상도 프리셋 → 해상도 적용**으로 작업 영역을 설정합니다. **모드 추가**는 현재 배치와 연출을 복사하며 각 모드는 독립적으로 편집됩니다. 같은 에셋 경로를 사용하지만 노드 속성 변경이 다른 모드에 자동 전파되지는 않습니다. 가로만 필요한 경우 한 모드로 작업하면 됩니다. 화면 구성의 고정/반응형 선택은 현재 문서에 저장되며 프로젝트 전역 기본 설정 파일을 작성하지 않습니다.

반응형 배치 세트는 현재 **수동 모드 전환과 모드별 기준 해상도 편집** 범위입니다. 창 크기에 따른 자동 breakpoint 전환, anchor 재배치, 중간 화면비 시뮬레이션과 게임의 반응형 설정 변경은 미구현입니다. 기준 해상도를 바꿔도 노드 좌표·배율은 유지됩니다. 게임용 내보내기는 현재 활성 원본 모드만 포함하며, 원본 기준 해상도를 변경한 모드와 복사한 사용자 모드의 게임 적용은 지원하지 않습니다. 모든 모드를 보관하려면 장면 JSON으로 저장합니다. 게임에 저장한 적용본 열기는 해당 모드만 엽니다.

## 검증

```sh
npm run typecheck
npm test
npm run test:browser
npm run test:desktop
npm run build
```

브라우저 테스트는 설치된 Chrome을 사용합니다. SlotClient 에셋·게임 역적용 검증에는 이웃 프로젝트와 설치된 게임 의존성이 필요하며 `npm run connect:slot`으로 연결을 설치해야 합니다. 테스트 에디터 5183과 실제 게임 5174를 사용합니다. 프로젝트 선택 테스트는 이웃 TemplateWebGame도 필요합니다. 데스크톱 테스트는 설치된 Electron으로 독립 창을 열고 OS 폴더 선택 응답과 닫기 확인 응답을 자동화합니다. 순수 데이터·파일 경로 테스트는 이웃 게임 없이 실행할 수 있습니다.

자동 검증 항목:

- active 전파, 월드 변환 보존, 순환·shear 거부
- JSON 왕복, 잘못된 문서·트랙·경로 거부, 평가 시 원본 보존
- 단일 화면 문서 호환, 모드별 배치·해상도·트랙 보존과 JSON 왕복, 비활성 모드 검증, 모드 전환·해상도 편집 undo/redo
- 한글·공백 에셋 경로, 프로젝트 밖 파일 접근 거부
- 실제 Chrome에서 계층 토글·숫자 편집·undo·JSON 다운로드/재import
- 실제 Chrome에서 해상도·화면비 적용, 모드 추가·전환·수치 보존·저장 복원과 SlotClient 가로·세로 세트 전환
- 실제 Spine·이미지 로딩, 플로팅·배치 저장·재시작 복원
- SlotClient 가로·세로 layout 렌더링과 브라우저 오류 검사
- 실제 SlotClient의 이미지·Spine 값 적용, resize 후 유지, 게임 적용본 재import
- 게임 파일 백업·교체, 잘못된 패키지·오래된 원본·미지원 수정 거부

## 남은 필수 작업

1. 배포용 데스크톱 패키징, 패널별 별도 OS 창·재도킹·다중 모니터·macOS 실기 검증
2. 게임 역적용 확대: HUD·로딩·에셋 변경·계층 편집·신규 노드와 연출·파티클 적용
3. 코드 연출 등록·공통 clock 연결, particle/Spine 이벤트 트랙과 정확한 seek·상태 복원
4. 폭죽·팝업·머니 이동을 게임 이벤트와 동일하게 실행하는 완전한 검수 예제
5. SlotClient 메뉴·기능 팝업·bitmap font·실제 릴 데이터·expand 좌표계·게임별 폰트 연결
6. 파티클 burst UI·전체 입자 수 제한
7. 홀덤·맞고 어댑터와 문서 버전 마이그레이션

이미지·Spine 배치는 실제 게임까지 검증했지만, **연출 트랙·파티클까지 게임 적용 완료로 보지 않습니다.** 시간 커서의 입자·Spine 상태는 아직 재시뮬레이션하지 않으며 UI에도 이 제한을 표시합니다. 독립 에디터 창과 패널별 별도 OS 창을 구분하여 후자는 미완료로 관리합니다.
