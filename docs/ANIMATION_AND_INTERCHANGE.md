# 지정 연출 미리보기와 게임 import/export

2026-10-21 추가 요구사항을 반영한 필수 설계입니다. 구현 완료를 의미하지 않습니다.

## 사용자가 원하는 결과

이미지·Spine·파티클을 개별 확인하는 데 더해, **화면 전체에서 실행되는 지정 이벤트 연출**을 확인해야 합니다. Timeline, 코드 또는 다른 방식으로 작성했더라도 연결 규약을 통해 선택·재생할 수 있어야 합니다.

대표 사례는 사용자가 제시한 **승자승 이벤트: 폭죽 + 팝업 + 획득 머니 이동**입니다. 에디터에서 확인·수정한 Transform과 애니메이션 정보는 export 후 실제 게임에서도 적용되어야 하고, 게임용 데이터를 다시 import해 수정할 수 있어야 합니다.

## 대표 시나리오

1. `승자승` 연출을 선택합니다.
2. 테스트 획득 금액, 머니 출발 노드와 목표 계기 노드, 화면 방향을 지정합니다.
3. 폭죽 발생, 팝업 등장·금액 표시, 머니 이동·팝업 종료를 하나의 연출로 확인합니다. 순차·병렬 관계와 시간은 데이터가 정합니다.
4. 전체 재생·일시정지·재시작·반복·배속을 사용합니다. 데이터 연출은 시점 이동으로 특정 장면을 확인합니다.
5. 노드 Transform과 연출 설정을 수정하고 게임용 패키지를 export합니다.
6. 실제 게임은 동일 패키지를 import하고 실제 결과 금액을 전달해 같은 연출을 실행합니다.
7. 에디터에 재import하여 계층·기본 Transform·연출 정의가 유지되는지 확인합니다.

예시 시간표의 구체적인 초 단위 값은 아직 정하지 않았습니다. 머니가 날아가는 방향·좌표는 화면 하드코딩 대신 안정적인 노드 ID와 anchor를 사용합니다. 실제 잔액 지급은 게임 로직의 책임이며 미리보기는 표시 값만 변경합니다.

## 연출 작성 방식

| 방식 | 데이터와 실행 | 미리보기 계약 |
| --- | --- | --- |
| 데이터/Timeline | 타깃 ID, 시작 시각, 길이, 속성·값, easing, 이벤트·파라미터 | 공통 실행기가 평가. reset과 시점 이동 지원 |
| TypeScript 코드 | 등록 ID·버전·파라미터, 게임과 공유하는 코드 모듈 | 명시적 create/play/pause/reset/dispose 연결. seek 가능 여부 선언 |
| 외부 형식 | 전용 어댑터가 공통 데이터 또는 등록 연출로 연결 | 지원 필드와 미지원 항목 보고, 동일 결과 검증 후 지원 표시 |

모든 기존 코드를 자동 분석해 Timeline으로 바꾸지는 않습니다. 게임 부팅이나 서버 연결 없이 실행할 수 있도록 필요한 노드·값·clock·난수·이벤트를 context로 주입합니다. 공통 runtime과 어댑터의 정확한 TypeScript API는 구현 단계에서 확정합니다.

최초 데이터 트랙은 위치·배율·회전·alpha, active, Spine animation/skin/loop, particle 시작·burst·정지와 텍스트·표시 금액을 대상으로 합니다. active는 조상 active와 함께 계산되며 꺼진 부모를 자식 트랙이 강제로 켤 수 없습니다. 트랙은 기본 상태 위에 임시 값을 적용하고 문서를 직접 변경하지 않습니다.

같은 노드·속성에 겹치는 트랙은 초기 버전에서 검증 오류로 처리합니다. easing은 등록된 이름과 파라미터로 표현하고 임의 함수를 직렬화하지 않습니다. 연출에서 발생한 화면 이벤트는 게임 지급·네트워크·파일 변경을 직접 실행하지 않으며, 미리보기용 핸들러와 게임 핸들러를 분리합니다.

## 시간과 상태 관리

- 이미지 tween, Spine, particle, popup 모두 공통 재생 clock을 기준으로 제어합니다.
- 일시정지는 현재 시각을 보존하고 정지·재시작은 초기 장면 snapshot으로 복구합니다.
- 임시 생성 노드·timer·tween·입자·이벤트 구독을 종료 시 정리합니다. 반복 실행 시 누적되지 않아야 합니다.
- 데이터 시점 이동은 초기 상태에서 평가합니다. 파티클과 이산 이벤트는 고정 step과 seed로 재시뮬레이션하고, 외부 부작용은 재실행하지 않습니다.
- 코드 연출은 seek를 구현하거나 reset 후 제한된 시간 동안 재시뮬레이션합니다. 불가능하면 해당 조작을 비활성화하고 이유를 표시합니다.
- 무한 연출과 긴 연출은 duration 또는 검수 구간을 선언하고 시뮬레이션 한도를 둡니다.
- 재생 중 기본 배치를 수정하려면 정지·초기화합니다. 트랙 편집과 기본 배치 편집을 구분하여 중간 상태가 원본에 저장되지 않게 합니다.

## 공통 게임 패키지

게임용 JSON은 단순 편집기 백업이 아니라 게임이 소비하는 정식 데이터입니다. 다음 정보를 포함하는 스키마를 정의합니다.

| 영역 | 교환 정보 |
| --- | --- |
| 버전 | schemaVersion, 필요한 runtime/adapter 버전, 프로젝트 식별자 |
| 화면 | 기준 해상도·방향, 좌표·화면 맞춤 규칙 |
| 노드 | stable ID, 타입, 부모·순서, activeSelf, 로컬 Transform, origin |
| 에셋 | 프로젝트 기준 상대 경로·식별자, Spine skeleton/atlas 및 선택 상태 |
| 연출 | ID, 타깃 ID, 트랙·시간·easing·이벤트, 반복 규칙, 테스트 기본값과 입력 스키마 |
| 코드 연출 | 등록 ID, 구현 계약 버전, 직렬화 가능한 파라미터 |
| 검증 | 필요한 지원 기능, 미지원·누락 참조 오류 |

선택 노드·패널 크기·줌·재생 커서는 게임용 패키지에서 제외합니다. skeleton 원본이나 코드 소스는 JSON에 내장하지 않습니다. 코드 연출의 로직 변경은 공유 코드 배포가 필요하고, 데이터 export만으로 새 코드가 생기지는 않습니다.

좌표는 부모 기준 로컬 값, 회전 단위는 도, 시간 단위는 밀리초로 통일합니다. 이미지 origin·Spine 원점 차이를 유지하며, 게임과 에디터에서 같은 화면 맞춤 계산을 사용합니다. 다른 화면 비율에서는 같은 숫자뿐 아니라 같은 기준·anchor를 적용해야 합니다.

stable ID는 배열 위치나 표시 이름에 의존하지 않습니다. import가 ID를 유지해야 트랙 타깃도 유지됩니다. ID·에셋 경로·버전·유효 숫자·트랙 타깃·코드 등록을 적용 전에 검증하고 누락 항목은 명시적으로 거부합니다. 최초 import는 문서 전체 교체 방식이며 변경 손실을 확인합니다. 선택 병합은 추후 범위입니다.

## 실제 게임 적용 계약

1. 게임 어댑터가 패키지와 에셋·연출 모듈의 호환성을 검증합니다.
2. 기본 layout 평가 후 export된 장면 데이터를 적용합니다.
3. 실제 게임의 이벤트가 공통 연출 runtime에 결과 금액과 타깃 context를 전달합니다.
4. 연출은 기본 Transform 위에 임시 상태를 적용하고 완료·취소 시 선언된 종료 정책을 적용합니다. 기본 정책은 편집 기준 상태 복원입니다. 머니 도착 후 계기 표시처럼 유지할 결과는 게임 표시 상태로 명시적으로 전달합니다.
5. resize·방향 전환 후에도 기본 layout → 공통 데이터 → 연출 상태 순서로 계산합니다. 프리셋·게임 로직·트랙이 같은 속성을 동시에 소유하지 않도록 합니다.
6. 잘못된 패키지는 적용 전에 거부하며 부분 적용으로 장면을 손상시키지 않습니다. 마지막 정상 데이터나 기본 layout으로 복구하고 오류를 표시합니다.

에디터에서 게임 파일을 export하는 것과 게임 어댑터가 이를 적용하는 것은 별개 작업입니다. 실제 게임 측 코드를 연결하고 검증해야 완료이며, 자동 TypeScript 원본 재작성은 필요 조건이 아닙니다. 실행 중 게임과 실시간 동기화하는 기능도 파일 import/export와 별개의 후속 기능입니다.

## 완료 검증

- 게임용 export → 에디터 import → 재export 시 stable ID·계층·Transform·active·연출 정의가 보존됩니다.
- 실제 게임에서 같은 입력·기준 해상도·방향으로 승자승 연출을 재생하고 시작·중간·끝의 위치, active, 애니메이션·입자 시작 순서와 목표 도착을 비교합니다.
- 부동소수점과 GPU 입자 렌더링 차이는 수치 허용 오차와 고정 seed·step으로 검증합니다. 모든 장치에서 픽셀이 완전히 같다는 보장은 하지 않습니다.
- 화면 비율 변경과 가로·세로 전환 후에도 머니 목표점과 팝업 위치가 같은 규칙을 따릅니다.
- 코드·데이터 연출 각각의 지원 기능을 확인하고 정지·반복·취소 시 자원 누적과 외부 부작용이 없습니다.
- Windows·macOS에서 파일 경로·대소문자·한글·공백 경로와 대표 재생 흐름을 검증합니다. 파일 저장은 각 운영체제의 로컬 서비스가 담당합니다.
