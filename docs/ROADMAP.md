## 1. 렌더링 가능성 검증

- [ ] TypeScript·Vite·편집 UI 기반 구성
- [ ] Phaser 캔버스와 Spine 플러그인 연결
- [ ] 실제 이미지 한 장과 실제 Spine 한 개 로드
- [ ] Phaser 파티클 하나 생성
- [ ] 세 타입을 같은 부모 아래 넣어 변환·그리기 순서·active 검증
- [ ] 일시정지·재시작·누락 에셋 오류 처리 검증

완료 조건: 서버 연결 없이 세 타입이 동시에 표시되고 부모를 끄면 표시와 갱신이 중단됩니다. 이 단계에서 Container 호환성과 Spine 버전을 확정합니다.

## 2. 계층 편집 MVP

- [ ] 공통 장면 문서와 검증 로직
- [ ] 트리 선택·펼침·접힘, active 체크박스
- [ ] 그룹 추가, 노드 추가·삭제·복제, 부모·순서 변경
- [ ] Scene 선택·드래그, 줌·화면 맞춤, 원점·선택 테두리
- [ ] Inspector 공통 속성 편집
- [ ] 실행 취소·다시 실행

완료 조건: 3단계 계층에서 자식 activeSelf를 유지한 채 부모 on/off가 동작하고, 이동·부모 변경을 되돌릴 수 있습니다.

## 3. 에셋별 편집과 저장

- [ ] 이미지 크기·origin·뒤집기·tint와 9-slice
- [ ] Spine animation·skin·loop·speed 및 재생 제어
- [ ] 파티클 설정·연속 방출·burst와 재생 제어
- [ ] 에셋 브라우저와 누락 파일 자리표시자
- [ ] JSON 저장·불러오기, 변경 여부·전환 처리
- [ ] 스키마·중복 ID·잘못된 부모·순환 참조 검증

완료 조건: 세 타입을 편집한 문서를 재열면 배치·계층·active·설정이 복원됩니다. 오류 문서를 열어도 기존 작업이 보존됩니다.

- [ ] SLOT_1002 가로·세로 layout 전용 어댑터

- [ ] 일반·프리스핀·메뉴·로딩 그룹과 활성 상태 프리셋
- [ ] 샘플 릴 심볼과 HUD 값 표시

완료 조건: 실제 SlotClient 화면과 나란히 비교해 지원 범위의 위치·크기·레이어 차이를 확인하고, 차이가 있는 항목을 문서화합니다. 게임 로직 없이 렌더링하는 범위를 사용자에게 표시합니다.

## 5. 게임 적용 및 다른 게임 확장

- [ ] layout override 규약과 stable ID 정책
- [ ] 게임 측 override 적용 코드 및 실제 반영 검증
- [ ] 홀덤·맞고 구조 조사와 어댑터
- [ ] 공통 속성과 게임별 확장 속성 분리
- [ ] 정렬·스냅·다중 선택 등 편집 편의 개선

완료 조건: 에디터 저장 결과를 실제 게임이 읽고 같은 위치로 표시하며, 다른 게임에도 공통 계층·active·미리보기 기능을 사용할 수 있습니다.

## 검증 우선순위

자동 검증은 계층 순환 방지, active 전파, 변환 계산, undo/redo, 저장 왕복, 경로 루트 이탈 방지처럼 실패 영향이 큰 규칙에 집중합니다. 시각 결과는 실제 에셋을 사용한 브라우저 검증으로 확인합니다.

최초 사용자 확인 시나리오는 **이미지·Spine·파티클을 같은 그룹에 추가 → 부모 off/on → 애니메이션·입자 재생 → 자식 이동 → 저장·재열기**입니다.
