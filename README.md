# PhaserEditorTool

Phaser 게임의 화면 배치를 눈으로 확인하고 편집하는 로컬 개발 도구입니다.

SlotClient와 홀덤·맞고 게임을 개발할 때, 좌표 코드를 수정하고 게임을 실행해야만 결과를 알 수 있는 불편을 줄이는 것이 목적입니다. Unity처럼 **계층 목록 → 화면 미리보기 → 속성 수정** 흐름을 제공합니다.

## 현재 상태

- GitHub: [lemon-toast/PhaserEditorTool](https://github.com/lemon-toast/PhaserEditorTool)
- 단계: 개발 버전 0.1 구현 및 Windows Chrome 검증
- 실행 가능한 도킹 에디터, 이미지·Spine·파티클 미리보기와 SlotClient layout 가져오기를 구현했습니다.
- SlotClient의 이미지·Spine 배치 역적용과 게임 적용본 재import를 연결했습니다. Electron 독립 에디터 창에서 프로젝트와 작업할 화면을 선택합니다. 전체 연출 역적용·코드 연출·패널별 별도 OS 창·macOS 검증은 남아 있습니다. [구현 현황과 제한](docs/IMPLEMENTATION_STATUS.md)을 확인하세요.

## 실행

Windows에서는 루트의 **`에디터 실행.cmd`를 더블클릭**합니다. 에디터 창에서 **프로젝트 선택 → 가로/세로 화면 선택 → 선택한 화면 열기** 순서로 시작합니다. **프로젝트 폴더 열기**는 OS 폴더 선택 창을 사용합니다. 게임 서버를 따로 실행할 필요가 없습니다.

처음 설치할 때는 Node.js 22.12 이상에서 다음을 실행합니다.

```sh
npm ci
npx install-electron --no
npm run desktop
```

현재 저장소와 의존성이 필요한 개발 실행 방식이며 배포용 설치 파일은 아직 없습니다. macOS용 `에디터 실행.command`도 포함했지만 실기 검증 전입니다. 실행 권한이 없으면 터미널에서 `sh '에디터 실행.command'`로 실행합니다.

SlotClient는 SLOT_1002 기본 레이아웃과 게임에 저장한 적용본을 선택합니다. TemplateWebGame은 현재 공용 에셋을 빈 화면에 추가하는 범위이며 기존 홀덤·맞고 화면 가져오기는 남아 있습니다. 폭죽·팝업·머니 이동 예제는 **예제 연출 열기**로 선택합니다.

화면 패널의 **배치 모드** 드롭다운 옆에서 너비·높이, 화면비와 해상도 프리셋을 바꾸고 **해상도 적용**을 누릅니다. 가로만 쓰는 고정 화면은 한 모드로 작업하고, **모드 추가**로 세로·태블릿 등 필요한 배치를 한 문서에 보관할 수 있습니다. SlotClient 기본 레이아웃은 가로·세로 원본을 한 세트로 엽니다. 반응형 배치 세트는 현재 수동 전환이며 자동 breakpoint·anchor 대응은 남아 있습니다.

브라우저 개발은 `npm run dev` 후 표시되는 주소로 접속합니다. 독립 에디터 창은 내부 파일 API를 함께 시작하며 5175 포트를 사용합니다. 이미 실행 중이면 기존 창을 활성화합니다.

## 1차 목표

- 이미지, Spine, Phaser 파티클을 같은 화면에서 확인
- 부모·자식 계층 표시와 노드별 active on/off
- 독립 패널 도킹·탭·분할·플로팅, 크기 조절과 워크스페이스 저장·복원
- 부모 비활성화가 모든 자식에 반영되는 미리보기
- 화면에서 선택·이동하고 Inspector에서 위치·크기·배율 수정
- Spine 애니메이션 선택·재생·일시정지, 파티클 재생·정지·재시작
- 가로·세로 화면 전환 및 배치 저장·불러오기
- 폭죽·팝업·획득 머니 이동 등을 묶은 이벤트 연출 선택·미리보기
- Transform·애니메이션 데이터 import/export와 실제 게임 적용 검증
- 게임 서버에 접속하지 않고 화면 작업

## 문서

**작업 저장 / 작업 불러오기**는 편집 문서 전체(`.scene.json`)를 보관하고 이어서 작업하는 기능입니다. **데이터 Import / 데이터 Export**는 게임 패키지를 주고받는 별도 기능입니다. 게임 데이터를 Import하면 작업 저장이 필요한 상태가 되며, Export하거나 슬롯에 적용해도 작업이 저장된 것으로 처리하지 않습니다. 현재 작업 저장은 파일 다운로드 방식입니다.

화면 배치 중 계층 또는 화면에서 **Ctrl/Shift 클릭**(macOS는 Command도 가능)으로 여러 객체를 선택합니다. 선택한 객체를 드래그하면 함께 이동하며, 부모·자식 동시 선택은 중복 이동하지 않습니다. 화면 패널의 **원점 X/Y 맞춤**은 마지막 선택 객체를 기준으로 정렬합니다. **격자 스냅**을 켜고 간격을 지정하면 드래그 기준 객체의 원점을 격자에 맞추며 상대 간격을 유지합니다. 정렬과 묶음 이동은 한 번의 실행 취소로 복구합니다. 다중 선택의 속성 입력·복제·삭제는 마지막 선택 객체에 적용됩니다.

## 기본 원칙

1. Phaser 기반 미리보기로 실제 게임과의 차이를 줄입니다.
2. 게임 로직 실행 없이 시각 요소를 확인할 수 있어야 합니다.
3. 편집 문서와 게임용 export를 구분합니다. Transform·연출 데이터는 게임과 공통 규격을 사용하고 실제 게임 적용까지 검증합니다. 기존 소스·에셋의 자동 재작성은 하지 않습니다.
4. 파티클은 우선 Phaser emitter를 지원합니다. 다른 엔진의 파티클 데이터 변환은 별도 범위입니다.
5. 여러 게임은 각 프로젝트의 layout과 에셋을 공통 장면 데이터로 바꾸는 어댑터로 연결합니다.
6. Windows와 macOS에서 실행할 수 있도록 TypeScript·Vue·Phaser 기반으로 설계합니다. 프로젝트 경로는 설정으로 선택하고 공유 데이터에는 상대 경로를 사용합니다.
7. Timeline 형태나 코드로 작성한 연출 모두 명시적인 연결 규약을 통해 미리봅니다. 시각적 Timeline 제작 UI는 별도 확장입니다.
